the warning says what it is, the structure is in the glossary, and `green_wash_probe` has a

## A Knot is a consequence, and the consequence was being forgiven

`RunSnapshot` takes one dictionary per system, and the Canker director did not contribute
one. So a run saved with two Knots open came back with a clean interior, the grace
running again from wave three, and the lost ground still on the board - the field was
saved, which is what makes this worse than a missing feature. The save restored the cause
and dropped the effect, and a player who quit rather than fight an interior front got the
front removed for quitting.

`CankerDirector.capture_state` / `apply_state` now hold up their end. `"cankers"` is a new
entry in `RunSnapshot.SYSTEM_KEYS`, captured after the field and applied after it too,
because the stages restored are claims about ground and are measured against the cells the
save brought back on the first evaluation afterwards.

**No save version bump.** `SaveStore.VERSION` stays at 1 and `MIGRATIONS` stays empty. A
file written yesterday has no `cankers` key, `RunSnapshot.get_system` answers an empty
dictionary for a system it has nothing for, and `apply_state` returns on an empty
dictionary - which leaves exactly the clean board an old save honestly describes. A
migration would be inventing Knots for a run that never had any.

### What is stored, and what is deliberately not

Parallel Packed columns over the site grid - stage, hold timer, warning timer, cooldown,
age, texture index, rotation - plus the site count and the run's redirect tally.

- **Positions are not stored.** The grid is derived from the arena, so the save carries
  what each site *is* and this build rebuilds where it sits. The count is stored to notice
  an arena that has been re-authored since, which is the same question
  `TerritoryField.apply_state` asks about the cell grid and is answered differently here:
  a mismatch drops the Cankers and lets the run resume, where a mismatched field refuses
  the run outright. A run resumed onto a clean board is still the run; one resumed onto
  the wrong ground is not.
- **The measured Rot ratio is not stored.** It is measured again on the first evaluation
  after the restore, off the field that *was* saved. A stored ratio would be a second
  opinion about ground already on file, and the two could disagree.
- **`flash_remaining` is not stored**, for the reason the snapshot keeps no enemies: it is
  a third of a second of pulse belonging to a spawn that is not coming back.
- **`age` is stored**, and this is the one that changes what the player sees. Age drives
  the emergence swell, so a Knot restored at zero would push up out of the ground again in
  front of somebody who watched it open before they quit. Restored, it comes back grown.

`apply_state` emits nothing. `canker_formed` and its siblings announce an *edge* - ground
just lost, ground just won - and a restored Knot is neither; firing them would tell a
player who pressed Continue that a Canker is forming.

## The warning says something

`canker_warning_started` fired into `_set_status`, which is a no-op sink in this build, so
section 22.3's "ROT TAKING ROOT" reached nothing at all. It is now painted on the board
beside the region, which is what the section actually asks for - the warning is a thing
happening *there*, and a banner across the top would turn a local consequence into a global
catastrophe. A second, shorter label names the Knot as it opens.

Three things had to be true for words on the field to be worth having.

**They must not be drawn under the walls.** The Canker layer sits at z_index 2 and the
arena's obstacle layer at 10, so the first frame of this came out reading `ROT TA    OOT`
with an interior wall through the middle of it - which is worse than no warning, because it
looks like a rendering fault rather than a message. Raising the director would have taken
the Knots and telegraph rings up with it, and those are *ground*: a wall in front of a Knot
should cover it. So only the words move, onto a `LabelLayer` child with an absolute z index,
which is exactly what `CombatDirector.DamageNumberLayer` exists for and is documented as
following it.

**They must stay inside the wall.** The label sits under the ring, and a site against the
bottom boundary would put its text through the stonework - the layer is clipped, so what
the player would actually see is the top half of a word. It is clamped back inside the
playable bounds instead. Insetting the sites is still the wrong answer for the same reason
it was wrong for the paintings: ground beside the wall is the first ground a player gives
up, so it is the likeliest place for this text to be needed.

**They must arrive with the thing they describe.** The text fades in over 0.3s from the
moment the warning starts, measured from the start rather than from what is left, so it
comes up with the second ring instead of arriving with the Knot. The name fades out again
after a couple of seconds: long enough to read once, gone before it is furniture. It is
keyed off `age`, which means a Knot restored from a save does not announce itself - the same
decision as the emergence swell, and for the same reason.

There is still no sound. That is deliberately left for now.

## Cankers are in the glossary

`CANKER`, two sentences, between BLOOM and CUTTINGS.

Yesterday this was parked because no reward text names one, and an entry the tooltip scanner
can never reach is the closed loop that got seven entries deleted on the 17th. What changed
is the paragraph above: the word is now on the board when a Knot opens, so a player meets it
and can go look it up. The entry leans on "Rot" and on "the ground", not on vocabulary that
only exists inside other entries, and `TERRITORY` is the only term in it that links onward.

The visual probe asserts the name actually renders, and says why in the comment: that check
is what makes the glossary entry honest rather than decorative.

## `green_wash_probe` says what it means

`paper_on_owned == 0` is now `paper_share <= 1%`, with the number reported either way.

Zero was never what the check meant. Reading the framebuffer back is not exact, and on the
17th that produced a deterministic 6036 of 1,762,381 owned pixels - 0.34% - on a tree with
nothing in it that touches the wash, reproduced on a clean worktree of `343b18b`. The
tolerance is not a weakening: Paper showing through the seam between cells would show along
*every* cell boundary, which at a 112x63 grid is on the order of an eighth of the owned
pixels. One percent sits an order of magnitude under the defect and three times over the
noise.

## The Hive Queen

The run has a second boss. She enters at Campaign Wave 20 and at 09:00 in Quick, between
the Burrower and the final invasion, and she is the first enemy in the game whose threat is
not her own body: she holds position out of reach and grows Colony Cores. The architecture
doc has said for months what she is - *"creates hostile cores through the Colonizer contract
and does not maintain a private copy of hostile territory"* - and that turned out to be the
whole design once it was taken literally.

The Burrower comes to you and erases ground on the way. She makes you come to her, across
the ground she has already grown. Killing her ends her but not her brood: the Cores outlive
her and still have to be cleared, which is the same message Cankers carry, and the reason
she pays a relic rather than a cleared board.

### `== BOSS` was right by accident

About a dozen rules elsewhere reduce an effect, raise a cap or refuse a spawn redirect
because the target is *a boss* - the overkill cap, the Mass Entanglement share, the fungal
collapse share, Mimosa's shove, Man-Eater's bite, Newton's falling body, whether a damage
number is important, whether a body keeps full detail in a crowd. Every one of them was
written as `role == EnemyKinds.Role.BOSS`, and every one was correct only because there had
never been a second boss.

They now ask `EnemyKinds.is_boss(role)`. That is the whole reason a new role was safe to
add: the alternative was remembering the Hive Queen in twelve separate files, and the
failure mode of forgetting one is a boss that quietly takes full damage from a crowd-control
pulse - a balance bug with no error message anywhere near it.

Both role enums gained `HIVE_QUEEN` at the **end**. Those values are stored - in
`enemy_profiles.tscn`, in authored wave tables, in a save - so their order is a file format,
and inserting a role beside `BOSS` would have silently renamed every role after it.

### A Colonizer that does not walk

The first version of her did almost nothing, and the probe caught it: she planted one Core
and then stalled at two for the rest of the fight.

`_try_establish_colony_core` refuses to plant while any Core is within `summon_spacing` *of
the Colonizer*, which is exactly right for a Colonizer - it plants at its own feet and must
walk away before it may plant again, so its brood is a trail it leaves behind. Handed to
something anchored, the same rule is a stall: plant once, never move, never plant again.

So `summon_offset_pixels` joins the profile. At zero it is the old contract, untouched.
Above it, Cores go on a ring at that radius and the spacing is measured *between Cores*
instead - a brood chamber rather than a trail, which is the shape her art was already
drawing. The angles are a golden-angle walk off her id and the size of the brood so far, so
a replayed seed grows the same chamber and successive Cores spread around the ring instead
of piling into the first free angle.

One more exception, in the same function. Cores are held down to a reserve while a milestone
is alive, so a milestone can always find room to enter a crowded arena. Applied to her, that
rule had her shrink her own brood *because she was on the field* - and she has already
entered. A boss doing the colonising is now exempt, and her authored brood of five is one
larger than the reserve precisely so the exemption is something a test can see.

### The art

Simple shapes, like the rest of the roster: a crimson mantle, eight spines, a dark chamber,
and a ring of teal eggs.

The palette is the argument. The crimson body and spines are the Colony Core's, the eggs are
the Colonizer's teal - she is visibly *made of* what she makes, which says what to do about
her before any text does. The eggs are also a readout rather than decoration: one pod per
Core she is allowed, lit for each Core standing on the board right now, so a player who has
cleared her brood can see that they have and a player who ignored it sees a full ring. Same
idiom as the Siege Corruptor's escalation arc.

### What it cost elsewhere

- **An eleventh relic opportunity.** `docs/relics.md` asks for 10-14 per run averaging 12;
  this moves a completed Campaign from 10 to 11, still inside the target and closer to the
  middle of it. `campaign_relic_count_probe` counts three milestone awards rather than two.
- **Wave 20 is "Devour" and grants no wave relic**, so her reward arrives on its own rather
  than in the same breath as a wave's. Wave 19, "Colony War", is the better thematic home
  and is a one-constant move if the pacing ever wants her earlier.
- **`hive_queen_spawned` is in the wave director's save state.** Without it a continued run
  would owe her again and put a second Queen on the board.
- **No Branch slot on her death.** There are two, and the Elite and the Burrower each open
  one; `unlock_branch_slot` would have refused anyway, and a reward that silently does
  nothing is worse than one the run never promised.
- **The campaign guide gained a 14.3 rather than a rewrite.** She was not in its schedule,
  so the section says so and is dated, which keeps the divergence visible to whoever reads
  the guide next instead of quietly restating the spec as if it had always said this.

## Two instruments, and what they said

`tools/balance_bench.gd` and `tools/pacing_probe.gd` are new, and neither is a test -
nothing in either passes or fails. They exist because every balance question in this
project has until now been answered by reading exported numbers and multiplying them by
hand, and that method cannot see reach, target supply, or the ground a build is standing
on. Thistle's thorn damage and Vine's sweep damage are not comparable quantities until
something fires both of them at the same enemies for the same minute.

The bench does that: same board, same held population of Hunters, all eight lines of a
Core pair at the same rank, everything stepped by hand at a fixed delta. All 28 pairs, at
rank 1, at rank 3, at rank 3 with the Evolution maxed, and again under siege - sixty
enemies entering at 130px, which is the only condition where "what does this build *stop*"
can be read at all. The pacing probe drives whole runs on the real wave clock and answers
each level-up by policy, recording what the player would have minute by minute.

The findings are in `docs/balance_and_pacing_sweep.md` and the proposals they lead to are
in `docs/balance_change_proposals.md`. Nothing has been applied to a balance number. Four
of the findings:

- **One Thornwhip rank is worth sixteen ordinary ranks.** Its first rank adds +50% to a
  pair that is already top-three, for one pick; taking all eight of that pair's lines from
  rank 1 to rank 3 - sixteen picks - adds +48%. It is the fourth multiplication on a chain
  that already has three, and the full ladder runs to +115% at rank 5. Neither mode reaches
  rank 5: Quick finishes at rank 1 and Campaign sits at rank 3 for its last twelve minutes,
  so a fix aimed at the ceiling would change nothing anybody plays against.
- **The territory Adaptations are not better at territory.** Spore+Root holds less ground
  than Thistle+Vine at every sample of a full run, earns less Biomass, and takes more
  damage under siege. At rank 1, nine pairs deal *exactly* the bare Cane's damage, to the
  digit: their first rank removes no bodies at all.
- **Pruning is the strongest Adaptation under pressure and nobody has said so.** Every
  Pruning pair took 17 damage across forty seconds surrounded by sixty enemies, where
  Thistle+Vine took 209, and four of the seven are top-eight for output.
- **Density is not difficulty.** Going from 22 enemies to 60 multiplies the mean build's
  output by ×4.8 against ×2.7 the threat, because arcs, ricochets and rings all hit more
  per activation while each body's health stays put. Quick's main escalation lever is
  spawn interval, so the schedule makes the player relatively stronger as it goes.

### Three bugs in the instruments, each of which reported itself as a finding

Worth recording, because all three produced *plausible* numbers rather than errors:

1. **The catalyst overlay never advanced.** Seeds, Blooms and Fruit are stepped by
   `TerritoryPrototypeOverlay._process`, and the bench's loop is synchronous - no frame
   passes inside it. Spore and Bloom rows came back identical to a build that had bought
   nothing, which reads exactly like a balance finding about Spore and Bloom.
2. **Grandma never turned.** Base Cane sweeps the sector she faces and Vine replaces that
   with auto-aim. A bench where she never turns is one where every non-Vine build fights
   at a quarter of its output, and every row would have been an argument for auto-aim.
3. **The player's `_physics_process` never ran**, so her invulnerability frames never
   ticked down: one hit made her permanently invulnerable and the damage-taken column read
   the same 6 points for all 28 pairs. That is the column Bramble and Root are paid in.

Each was found by a number that was too tidy - eight identical rows, a quarter of the
expected damage, the same 6 everywhere. That is the argument for printing raw columns
rather than an index.

## Tests

```
powershell -File scripts/run_tests.ps1 -SkipPerformance

46 test(s), 737 check(s), 0 failed.
All tests passed.
```

Ten new checks in `canker_probe`, three in `canker_visual_probe`, one in
`smoke/persistence`, and twenty-four in the new `hive_queen_probe`.

`hive_queen_probe` is three probes in one file on purpose, because the three things that
have to be true about her do not imply each other. Her schedule is driven on the real clock
rather than by spawning her, so what is proven is the milestone firing once - including that
she waits out the wave's opening break the way the Burrower does. Her brood is driven with
`simulate_step`, and that is what caught the stall above. Her boss-ness is asked through the
new predicate *and* through two of the rules that depend on it, because a predicate nothing
consults would pass on its own.

`enemy_role_probe` needed no edit: it already spawns every role the enum declares and
measures ink, so a role with no case in the draw match cannot be added without it noticing.
That is a check paying for itself.

The round trip is driven through `reset_director` in between rather than by applying the
state over itself, and the reset is asserted to have emptied the board first. Without that
step every check afterwards would pass against a board that was never cleared - which is
the same trap the persistence smoke test's "a fresh run is the control" block exists to
avoid, and it is worth being explicit that a restore test with no teardown in it proves
nothing at all. The state also goes through `var_to_bytes` before it is applied, because
the columns are Packed arrays and the encoder is where a Packed array's type is kept or
quietly widened.

Both failure paths are checked on a live board: a save whose `site_count` is off by one
grows no Knots, and an empty dictionary - every save written before yesterday - leaves the
board as a fresh run made it.

The check in `smoke/persistence` is structural rather than behavioural on purpose. The
prototype run has no Knots to lose, so what it can honestly assert is that the snapshot
carries a Canker board at all, site for site; what a saved Knot comes back *as* belongs in
`canker_probe`, which has a board with two on it.

The text checks in `canker_visual_probe` are **differences between two frames** rather than
counts of pale pixels, and both ways of getting that wrong happened before it was. The first
attempt counted an absolute number in a band under the site and reported no text at all -
the run had advanced far enough for a relic choice panel to be open across the middle of the
field, with the label behind it. The same attempt *passed* the edge case, off pale stonework
near the wall. So the interface layer is hidden for these frames, and each check measures the
same band with the site warning and with nothing there: the board is identical but for the
words, and neither a panel over the top nor a wall behind can fake the difference.
