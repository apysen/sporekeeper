# 2026-09-09

## The relic tray is a scene, and the run scene has no interface region left inline

`Interface/UpgradeTray` was the last one, named after a thing it does not hold —
it holds relics, not upgrades. It is now `scenes/ui/hud/relic_tray.tscn`, instanced
as `Interface/RelicTray`, and the name says what is in it.

| | before | after |
| --- | --- | --- |
| `run.tscn` nodes | 62 | **60** |
| `run.tscn` lines | 812 | **774** |
| `RunRoot` exported references | 51 | **50** |
| `run_root.gd` lines | 2064 | **1986** |

`RelicTray` owns the row and how it draws: which relics are held and in what order
they were taken, the rarity colour on the slot itself, the trigger counter a relic
needs readable without a hover, and the one empty socket past the end that says
more are coming. Two exports collapsed into one — `relics_label` and `relic_slots`
were the label and the row of a thing that had no name, and now the thing has a
name and the run root holds `relic_tray`.

The authored numbers stayed authored where they were. `relic_reward_wave_cycle` is
still an Inspector export on the run root, because the cadence at which the run
pays out a relic is a run rule; the tray is handed it through `setup()` so its
empty socket can name where the next relic comes from without that number being
typed a second time. Same rule the Adaptation tree follows with
`root_potency_note_template`.

`_maximum_relic_slots` went with it. The authored row length is the ceiling the
row grows toward, read once in the tray's own `_ready` before the first `refresh`
trims it — which is where it always belonged, since the only thing that ever read
it was the trim.

## Two rows, one tooltip stack, and a handler that finally admits it

`_on_hud_slot_hovered` and `_on_tree_slot_hovered` were the same function twice.
One took a row and dug the wording out of it; the other took finished wording.
Once the relic row could dig its own wording out — the way the Adaptation tree
already did — only the second was left, and it is now `_show_slot_tooltip`, which
both rows connect to.

Neither row shows its own tooltip, deliberately. The stack they would draw into is
shared with reward hovers that belong to neither of them, so a row reports what was
hovered and where, and the run root decides what to show. That is the same split
the Adaptation tree established; the relic row is now on the correct side of it.
